# AG60 界面样式检查

遵循仓库 `AGENTS.md`。检查和总结只读，用户要求修改时才改界面。仅要求优化 UI 时，调整布局、间距、尺寸、字号和控件样式，保留现有文案、提示及文字资源。保留现有可见元素及其含义，以及页面已有的主次区域比例、操作区的分组、顺序和行数。涉及改变分栏比例、拆行、合并或移动操作组时，先说明具体问题和改动范围，并获得用户确认。需要新增或删除文字、编号、图标、徽标、底托等可见元素，或调整文案、交互和状态逻辑时，须先明确指出变化并获得用户确认。处理对比度时，优先调整已有元素的颜色。

1. 用页面名、字符串、ID 或 Fragment 定位布局。按需追踪宿主、`include`、资源变体及运行时状态。
2. 按背景与页签、卡片、字段、操作区逐层检查。按需查[样式表](references/ui-styles.md)和[排版与尺寸规则](references/review-rules.md)，只读取相关小节。每个存在的界面层都做实际样式核对。找同模块同用途页面作参照，沿控件或宿主、资源绑定、继承与主题、XML 和运行时覆盖找到最终属性；未显式绑定时检查回落的默认值。
   - 发现顶部页签时，逐页核对实际生效的样式：定位 XML 控件和绑定的公共样式，检查样式继承、XML 的背景与内边距覆盖、Kotlin 的颜色覆盖及控件默认值。将轨道、选中背景和文字色与同模块同用途页面对照。仅使用相同控件类时仍要查样式绑定；缺少绑定且落回默认值时，报告具体差异。结论给出目标及参照的文件位置，以实际声明和调用为依据。
   - 背景、卡片、字段与操作区按[生效样式核对](references/review-rules.md#生效样式核对)检查。逐页按[统一边距表](references/review-rules.md#外边缘与状态)核对页面外缘、页签上下、相邻卡片、同一卡片内的连续输入行和固定底栏。切换页签时检查内容外缘和按钮下缘的对齐。弹窗和侧面板单独核对标题栏到第一个可见字段的总留白。
3. 对明确偏差给出目标位置、实际生效值、期望值及参照位置。源码无法确定的状态列为待实机确认。每项修改都要能指向适用的项目规则、同用途页面的生效做法，或用户明确提出的要求。仅有个人偏好或未经确认的风险时，记录观察，保留原样。交付前逐项对照差异与依据，撤回缺少依据的调整。优化时复用公共资源，保留绑定 ID、交互和状态逻辑，按仓库约定验证。

## 确认与回写

1. 建议存在疑点时，主动指出具体位置、项目依据、可能的影响和可选处理方式。涉及范围变化或需要用户取舍时，先确认该项；范围内明确的修改可继续。
2. 每次修改界面的收尾都检查本轮有没有新确认的通用规则，包括用户指出的错误、接受的例外和实机反馈。把可复用的结论在本轮回写到本技能：工作流程和范围边界写入本文件，具体样式和尺寸依据写入对应参考文件。改已有规则时直接修正原条目，写清适用条件，避免重复。
3. 尚未确认的建议和单页取舍留在当前任务。没有新的可复用结论时，技能无需改动。回写后在交付时简要说明更新了哪条规则。

## 技能维护标准

每次新增或修订样式规则时，同时检查规则是否写明适用场景、需要读取的证据、实际值如何与参照对照，以及何时判为偏差。发现已有标准却在评审中漏查时，把检查动作接到主流程或必读参考，补齐默认值、覆盖和状态的核对方法。规则名称和参照页只提供定位线索。优先修订原条目。修改前先找到同用途页面，追到实际生效的容器、公共样式和运行时设置，并优先复用同一做法。页面局部属性直接写在目标布局。共享尺寸按用途归组，连续的尺寸档位保持完整，页面横向净距这类按用途定义的尺寸单独分组。遇到现有做法看似无效，先核对是否漏了运行时设置、资源变体或系统版本差异。现有控件、样式和实现都无法满足时，说明依据与必要性，经用户确认后再新增自定义控件或专用样式。

用触发修改的真实案例回查，确认新步骤能指出原先漏掉的差异；有正常参照时也走一遍，确认合法变体不会被指为偏差。对依赖实机的判断，说明需要观察的状态。
