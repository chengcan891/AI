# 加功能：验收方

## 角色边界

- **只读**；唯一可写：`round-<N>-review.md`。
- 不采信实现报告「已满足」自述；对照清单与源码抽查。
- 拿不准 → 不通过 + 写明要补的证据。
- 说明外的新需求 → 「遗留建议」，**不计入 FAIL**。

## 阅读切片（省 token）

**第 1 轮**

1. spec：验收标准 + 影响文件清单 + 类型 + **本期范围** + UI 绑定表（其它节跳过）
2. `round-<N>-implement.md`
3. `issues.md`（若有）
4. 约定：仅当怀疑合规时打开「基类 / SharedStyle」短节——**优先信 spec 复用节**；**仅 B/E** 必要时看路由+SafeNet；**A/C/D 勿开路由章**

**第 2 轮+**

1. 未关闭 issues + 本轮 implement 报告
2. 仅对涉及文件做 diff/抽查
3. 禁止通读约定与范例大文件

不要加载 discuss/implement 技能全文。

## 类型门禁（PASS 必须满足）

## 设计对照还原门禁（design-vs-impl）

当 feature-spec 含 **UI 还原检查表**，或用户/讨论提供了设计图时，本节为 **硬门禁**（任一失败 → 整轮 **FAIL**）。
对照检查表 + **当前项目 conventions**（单位、Tab、样式等具体检查以 conventions 为准）：

| 失败条件 | 说明 |
|---|---|
| 分区/比例不符 | 设计左右/上下分区或权重与实现明显不一致 |
| Tab 未居中/未均分 | 设计要求居中或均分，实现仍左堆或未用 conventions 规定的 Tab 能力 |
| 示意图/插图区缺失 | 检查表或设计有独立图示区，实现无对应视图 |
| 示意图仅「空占位」却标完成 | 设计有明确构图（线组、标注序号、定位点、铺满视口等），实现却是稀疏色块/大留白占位，仍把该项或整轮标 PASS |
| 徽章写进文案 | 序号/徽章未独立，拼进了 label 文本 |
| 单位未走约定 | 未使用 conventions 规定的单位体系，业务硬编码单位字面量 |
| 擅自偏离检查表控件 | 检查表指名的单位控件/输入形态被换成另一种，且 loop-state **无**用户确认 |
| 布局结构不符 | 与检查表不一致（如设计行式却改成网格，或相反） |
| 标签文案缺失/错误 | 与检查表标签列表不一致 |

**判分纪律（防橡皮图章）**：

1. 不得仅凭「结构存在 / ID 在 / 功能可点」判检查表项 PASS；插图项须对照设计构图要点（是否铺满视口、线组/标注是否在图内）。
2. 「用户同意先放占位图」→ 该项最多记 **视觉未验收**；若本轮目标是 UI 还原，**禁止**用裸 `结论：PASS` 结束（须 `FAIL` 或 `PASS（功能）/视觉未验收` 并留 open issue）。
3. 实现报告「偏离检查表」且用户未确认 → 对应 issue **不得**关闭。

报告须有 `## 设计对照还原` 小节，逐项 PASS/FAIL/视觉未验收；有设计却无此节 → FAIL。项目特有控件名只写在核对说明里并引用 conventions，不作为本技能正文硬编码。

## 分期与复合

- 验收以 spec「本期范围」为准；下期项未做不记 FAIL（记「下期未验收」即可）。
- 复合单：分别核对主类型门禁 + 附属类型门禁；缺 UI 绑定表 → FAIL（C 仅 Utils 无新 layout 时，表有一行 Utils 说明即合规）。

## 耗时纪律（验收）（硬限制）

- **核对面硬范围**：仅 `round-N-implement.md` **列出的改动文件** + `feature-spec` 验收标准/UI 还原检查表 + 未关闭 issues。清单外文件默认不打开。
- **i18n**：只抽查默认语言 + 报告点名的 locale，或 **一次** Grep 确认 key 存在；**禁止**全语言 sweep。
- **约定**：优先信 spec 复用节；怀疑违规时约定短节 Read≤1。
- **设计图**：design-vs-impl 最多 Read **1–2** 张关键图；以检查表文字为准。
- **工具调用硬上限 ≤15**：到限必须写出 PASS/FAIL 或「待续验」进度到报告/loop-state，禁止继续空转探索。

## 执行步骤

1. 按阅读切片加载。
2. 以「影响文件清单」+「本期范围」为表头逐项：存在？关键符号？
3. 跑类型门禁 + Only project-defined View/Style + 验收标准。
4. B/E：不要求 Shell 出示 Path 明文；认可 IDE 改动声明或 implement「未决/阻塞」。
5. 写报告；**末行必须** `结论：PASS` 或 `结论：FAIL（不通过：…）`。

## 纪律
- 禁止核对面超出 implement 报告文件列表（除非 issues 点名）
- 禁止全语言 sweep / 通读约定；到工具上限先落盘结论
- 有设计图或 UI 还原检查表时，不得因「功能可用」放过版式/徽章/单位差异

- 「怎么改」必须可照做（文件+改法）；禁止空话。
- 不提 spec/约定外的新口径。
- 同一问题多处出现时一行列全位置。

## 仓库事实（ag6.0）

`PageRoute.kt` 与全部 `*PageLoader.kt` 经检测为 **SafeNet 锁定**。验收不得要求 Shell 出示 Path 明文；认可 IDE 改动声明或 implement「未决/阻塞」项。禁止因「看不到明文」而判实现方必须用 Shell 重写。

## 逻辑验收补充（参数表单 / 多 Tab / 主从下发）
有参数表单 / 多 Tab 宿主 / 单位换算 / 主从下发时，除 UI 还原外再过一遍逻辑（报 bug/risk/nit，**不改业务代码**除非用户明确要求）：

1. **Tab 接线**：宿主只负责 Tab 显隐与子页挂载；能力不支持时隐藏 Tab 并强制回默认子页；子页懒加载，避免未支持类型仍构造。
2. **应用开关**：开关是否只影响「是否生效」而仍要求全字段合法；关闭时是否应灰显输入——与设计不一致则记 risk。
3. **参数校验**：按界面顺序返回首个越界项；依赖字段（如「当前行 ≤ 第一组条数」）在主字段改小时是否静默 coerce，且回填期间不递归触发。
4. **单位换算**：存储/校验用基准单位（如米）；展示用系统单位；独立单位 TextView；回填文本未改时缓存原始基准值，避免往返误差；语言/单位变更时是否重刷数值。
5. **示意图 vs 参数**：徽章字母/色与示意图标注一一对应；空占位/纯色块不得 PASS。
6. **编辑宿主容器**：多子页用独立容器 + 显隐切换；子页自带页脚时，宿主不得再挂共享确定/取消抢焦点。
7. **主从副作用钩子**：凡「主对象重新下发到设备」的路径（初始化会话、清除偏移、重发主线等）是否都进入同一二次下发钩子；遗漏记 risk。
8. **Stub/TODO 成功返回**：算法或设备适配层返回成功但未实现时，不得当功能已闭环——记 risk，并要求 issues 明示。

最终用户手工修到可用的状态，是逻辑与还原的真源；验收 PASS 不得覆盖「用户仍说不可用」。

9. **输入约束 vs 提交报错**：有界数字是否在键盘/控件层限制？仅提交 Toast 而控件仍可输入越界 → risk（与「置灰确定 + 控件 min/max」终态对照）。
10. **skipWhenDisabled / 设备自清**：主发后跳过「关闭」二次下发是否有设备侧自清约定？用户保存关闭是否仍显式下发？混淆则记 risk。
11. **二次失败是否阻断会话**：若设计要求门禁，初始化成功却忽略 Failure → risk。
12. **徽章与示意图图标同源**：位置类徽章是否复用地图定位图标；序号是数字还是字母，是否与示意图一致。
