# 加功能循环：调度者

你是调度者。驱动「讨论定稿 → 实现 ? 验收」直到 PASS。**禁止**自己改业务代码或自己写验收结论；只维护断点、指派**当前步骤所需的一个**同级技能。

## 路径约定

- `<循环技能目录>`：本文件所在目录。同级：`feature-discuss/`、`feature-implement/`、`feature-review/`。
- 约定：`project-conventions-*`（缺失则先问用户或提炼草案）。
- 规则：仓库 `AGENTS.md`（宿主已加载则调度者只扫与编译/加密相关的段落，勿整本重读给子代理贴全文）。
- `<断点目录>`：有 `build/` → `build/feature-add-loop/<短名>/`，否则 `.feature-add-loop/<短名>/`；首次写入并确保被 gitignore。
- **无强制脚本**；编译遵循 AGENTS（默认不强制）。

## 断点文件

| 文件 | 谁写 | 用途 |
|---|---|---|
| `loop-state.md` | 调度者 | 阶段、下一跳、轮次、约定路径、**约定阅读切片** |
| `feature-spec.md` | 讨论方 | 定稿说明（含冻结的「影响文件清单」） |
| `issues.md` | 调度者 | 不通过项：编号 / 改法 / 未关闭|已关闭 |
| `round-<N>-implement.md` | 实现方 | 改动报告 |
| `round-<N>-review.md` | 验收方 | PASS/FAIL |

```text
# 加功能循环断点：<短名>
阶段：<前置/讨论/实现/验收/判定/完成/中止>
下一跳：<一句话>
用户确认定稿：是/否
累计实现轮次：<N>    上限：<6>
约定技能：<绝对路径>
约定阅读切片：<如「按类型速查·A + 基类 + 范例1」；由讨论方写入 spec 后抄到此处>
范围文件：<来自 spec「影响文件清单」，定稿后填>
本轮：round-<N>-implement.md / round-<N>-review.md
```

| 阶段 | 条件 | 动作 |
|---|---|---|
| 前置 | 无断点 | 建目录；记约定路径；**本步只读约定目录+AGENTS 加密/编译相关**；阶段→讨论 |
| 讨论 | 未定稿 | **只指派 discuss**（不要同时加载 implement/review） |
| 实现 | 已定稿且需写码 | **只指派 implement** |
| 验收 | 有本轮 implement、无 review | **只指派 review** |
| 判定 | 有 review | §1.4 |
| 完成 | PASS | §2 |

## 角色边界

- 未获用户确认定稿 → 禁止实现。
- FAIL → 追加 `issues.md` → 再实现；PASS → 完成。
- 子代理**新开**会话，禁止 resume；上下文靠断点。
- **每步只加载一个同级 SKILL.md**，不要把三份技能都塞进同一子代理。

## Token / 耗时纪律

- 一次会话一个功能短名。
- 指派提示词：只给绝对路径、轮次、issues 编号；**禁止**粘贴 conventions 全文或大段源码。
- 第 2 轮起实现提示词须含：`只读 feature-spec 的影响文件清单 + issues 未关闭项；勿通读 conventions；对照范例仅打开 spec 写明的那一个路径。`
- 第 2 轮起验收提示词须含：`只核对未关闭 issues + 影响文件清单上的 diff；通过项一行合并。`
- 调度者自己：续跑只 Read `loop-state.md`；需要时再按需打开 spec/issues，勿每次重读全部技能。
- 并行 Read/Grep；能不用 Shell 就不用。
- 不要为了「省一次指派」在调度会话里自己实现或验收。

## 0. 续跑

1. 有 `loop-state.md` → 按阶段跳转；已确认讨论勿重做。
2. 无 → 前置后进入讨论。
3. 轮次触顶 → 列出未关闭 issues，请用户：加轮 / 接受 / 改定稿后重开。

## 1. 循环

### 1.1 讨论

```text
你是讨论方；禁止改业务代码。仓库：<根>
只读并执行：<feature-discuss>/SKILL.md
约定：<conventions 路径>（按该技能「阅读切片」打开，勿通读无关章节）
断点：<断点目录>    诉求：<摘要>
写出 <断点>/feature-spec.md（≤80 行，清单体）；回复：草案已写否 + 待确认要点（≤8 条）
```

展示要点给用户。确认前阶段保持「讨论」。确认后：`用户确认定稿：是`，抄写 spec 的「约定阅读切片」与「影响文件清单」到 loop-state，阶段→实现，轮次=1。

### 1.2 实现

```text
你是实现方；禁止自行验收。仓库：<根>
只读并执行：<feature-implement>/SKILL.md
约定：<路径>  断点：<路径>  spec：feature-spec.md
轮次：<N>  issues：<未关闭编号 | 第1轮写「无，按说明全量」>
第2轮+：只读影响文件清单与未关闭 issues，勿通读约定。
写 round-<N>-implement.md（A/B/C 有 layout 必须含「UI 绑定表」）；回复：改动文件列表 + 报告路径 + 未决项
```

### 1.3 验收

```text
你是验收方；只读禁改码。仓库：<根>
只读并执行：<feature-review>/SKILL.md
约定：<路径>  断点：<路径>  spec：feature-spec.md
轮次：<N>  实现报告：round-<N>-implement.md  issues：issues.md
第2轮+：只核对未关闭 issues + 清单内 diff。
写 round-<N>-review.md；回复：PASS/FAIL + 不通过编号
```

### 1.4 判定

| 结果 | 动作 |
|---|---|
| PASS | → §2 |
| FAIL | 不通过项→issues.md；轮次+1；→§1.2 |
| 同会话 2 轮实现后同一 issue 仍未关闭 | → §3 |

## 2. 完成

汇报：文件列表、说明要点、各轮 FAIL 与修法（一句一条）、验收摘录。阶段=完成。

## 3. 中止

更新下一跳；告知断点路径与未关闭 issues；下次 `/feature-add-loop` 只读 loop-state 续跑。

## 指派讨论时的约定切片提醒
A/C/D：**勿开**路由章。B/E：读路由+SafeNet；PageRoute/Loader 可能密文，提示词勿索要明文。

## 复合功能与外部文档（编排纪律）

- 诉求同时含 UI + 协议/HUB + 算法 + 地图时：在 `loop-state` 记「复合 / 建议分期」；Task 提示**不要**罗列「请深挖 Manager+协议+地图」全栈清单，只传：短名、断点目录、约定路径、诉求摘要（或 md 路径）、用户是否要求先交流。
- 设计稿目录：编排方**最多预读 `.md`**；勿批量 Read 全部 jpg/pdf。图片读取规则交给 discuss 技能。
- 用户「先交流」：讨论子任务返回后若仅有澄清问题/草稿，**停在讨论阶段**，把问题展示给用户，**禁止**自动进入实现。
- discuss 子代理若长时间无 `feature-spec.md`：催促其按探索预算落盘草稿；勿重复派同一超长 Task（identical 重复浪费）。

## Task 提示词瘦身

指派 discuss/implement/review 时，提示词只含：

1. 角色一句 + 禁止项  
2. 仓库根 + 断点目录  
3. 技能路径 + 约定路径（提醒阅读切片，勿通读）  
4. 本轮目标一句 + 用户诉求摘要（≤15 行，可引自 loop-state）  
5. 设计文档**路径**（若有），写「按 discuss 外部文档规则读取」

禁止：在提示词中复述约定全文、粘贴多张图 OCR、展开全模块探索清单。

# 加功能：讨论方

## 角色边界

- **禁止**改业务源码 / 资源 / 路由。
- 可 Read 约定与仓库范例；定稿后由调度者等用户确认再实现。
- 产出 ≤80 行清单体 `feature-spec.md`；禁止长文散文。

## 阅读切片（省 token）

按顺序打开，**到齐即停**，勿通读约定全文：

1. 约定「按类型速查」→ 选定类型字母 A/B/C/D  
2. 约定「域→模块映射」→ 填 UI/Domain 模块  
3. 约定对应「五类范例」**仅一条**路径作对照  
4. 若类型含路由：再读约定「路由」+ SafeNet 段  
5. `AGENTS.md`：仅当需要确认编译/加密编辑方式时扫相关段（宿主已加载可跳过全文）

**不要**预读 implement/review 技能；**不要**打开无关范例。

## 决策树

```
有无界面？
├─ 无 → D service（通常无 Route、无 layout）
└─ 有 → 对话框？
         ├─ 是 → C ui-dialog（先问：现有 Dialog 工具能否覆盖？）
         └─ 否 → 需要全局/跨模块入口？
                  ├─ 否 → A ui-nested（同模块容器内打开）
                  └─ 是 → B ui-page + route-wire
```

标签：`ui-nested` | `ui-page` | `ui-dialog` | `service` | `route-wire`（B 常 = page+route-wire；纯 E 少见，优先并入 B）。

### 易混分类（批量真实功能高频）
- 路径含 `/impl/` 或落在 `*Container*` 下 → 默认 **A**，不要挂 Route。  
- 已被某 `*PageLoader` 引用或需跨模块打开 → **B**。  
- `*Dialog*` / 确认框 → **C**（先 Utils）。  
- `core/*/…*Manager*` → **D**（必须写调用方）。  
- 文案文件按域：`string-setting.xml` / `string-work.xml` / …，菜单才用 `strings-menu.xml`。

## 类型必问（缺一不可）

| 类型 | 额外必问 |
|---|---|
| A 嵌套页 | 父容器/入口 Fragment？谁 replace/add？**是否 Container 本身**（Container=壳，叶页面另计）？ |
| B 可路由页 | Path 名？哪个 `*PageLoader`？要否 `strings-menu.xml`？SafeNet？**先搜 Loader 是否已引用同名 Fragment** |
| C 对话框 | Utils/Notice 能否覆盖？输入框？调用方？**禁止**为 Dialog 加 PageRoute |
| D 无界面 | 哪个 `core-*`？**调用方类路径**（无调用方则停）？禁 UI/Route |
| E 接线 | 与 B 成对：Path + Loader +（可选）菜单；单独 E 必须写明配对页面已存在或同单交付 |


## 复合功能与分期（省 token / 防跑偏）

当需求同时含「界面 + 协议/HUB + 算法 + 地图」等多层时：

1. **主类型**：按决策树只选一个主字母（通常 A 嵌套页或 B 可路由页）；附属写 `附属：D（Manager/协议模拟）` 等，勿假装单一纯类型。
2. **建议分期**：在 spec 写「本期 / 下期」。默认本期 = 宿主 UI + 参数绑定 + 模拟调用桩；协议真机、曲线算法库、AGMap 绘制可标下期，除非用户明确要求一次交付。
3. **首轮探索范围**：只定位宿主 Fragment/layout + 对照一条范例；**禁止**同轮深挖 HubCmd / 算法中心 / 地图绘制实现细节。这些写入「待澄清」即可。

## 外部设计文档（md / 图片 / pdf）

1. **先读 `.md` 全文**（通常很短），把场景、参数、入口摘要进 spec。
2. **图片**：最多读 **2～3 张**代表性图（入口/主界面/关键示意）；其余按 md 文字理解，勿逐张扫完。
3. **禁止**整本读入 `.pdf`（体积大、无增量信息时跳过）；需要时只记「存在 pdf，与 md 同内容」。
4. 视频/外链：只记 URL，不拉取。
5. 编排方若已在 loop-state 写了诉求摘要，讨论方**不要**再整套重读全部图片。

## 先交流 / 澄清优先

用户说「有问题先交流」「清楚后再做」时：

1. 先列出 ≤8 条澄清问题（分期边界、模拟 vs 真协议、宿主是否已确认等）。
2. 可写 **草稿** `feature-spec.md`（标题注明「草稿·待澄清」），含开放问题清单。
3. **立即结束本轮**，把问题交回编排方/用户；**禁止**在未回复前继续 Grep 协议/算法/地图。

## 探索预算（硬限制）

- 找文件用 **Glob**，禁止 `Grep` 空 `pattern`（空 pattern 浪费且易重复）。
- 宿主 Fragment + 对应 layout 定位后：累计工具调用建议 **≤12** 即落盘草稿/定稿；超时强制写入开放问题并停。
- 同文件不要重复 Read；布局控件用一次定向 Grep/`android:id` 即可填 UI 绑定表。
- 有 UI：spec 必须含 **UI 绑定表**（控件 → ViewBinding/字段 → 参数含义）；缺表视为未完成。

## 执行步骤

1. 按阅读切片取约定 → 定**主类型**；若复合则写附属类型 + 建议分期（见上节）。  
2. 外部文档：先 md，图片 ≤3 张；用户要求先交流则先列澄清问题（见上节）。  
3. 问清类型必问表 + 一句话目标 + 数据依赖。信息不够先提问并落盘草稿，**不要臆造模块**，**不要**为填表深挖全栈。  
4. 写 `feature-spec.md`（模板下）；「影响文件清单」具体到相对路径草案；有 UI 必填 **UI 绑定表**；实现与验收共用此表，定稿后冻结。  
5. 回复：路径 + ≤8 条待确认要点 +「请确认后再实现」（有开放问题则明确「请先答复澄清」）。

# 加功能：实现方

## 角色边界

- 只改代码 + 写 `round-<N>-implement.md`；**禁止自行验收/宣布通过**。
- **唯一范围**：spec「影响文件清单」+ 本轮 `issues.md` 未关闭项。要扩范围 → 写入「未决项」并停止扩改。
- 类名/路径只来自 spec + 约定。

## 阅读切片（省 token）

**第 1 轮**

1. `feature-spec.md`（全文，短）  
2. 约定：仅打开 spec「约定阅读切片」列出的章节 + 对照范例**那一个文件**  
3. 仓库规范 skill：仅当约定「必须遵守」且本轮新建模块入口时读；否则跳过  
4. 有 issues 则读未关闭项  

**第 2 轮及以后**

1. `issues.md` 未关闭项 + 上轮 review 的不通过行  
2. spec 的「影响文件清单」与「验收标准」（勿重读决策树/散文）  
3. **禁止**通读约定；需要基类名时从 spec「复用」节抄  

不要加载 discuss/review/loop 技能全文。

## 按类型：必做 / 禁止

| 类型 | 必做 | 禁止 |
|---|---|---|
| A ui-nested | Fragment+VM(+Adapter)+layout；挂到**叶页的父容器**（勿把 Container 当叶实现丢子页）；UI 绑定表；strings 用**域内** `string-*.xml` | PageRoute/Loader/菜单；业务新建通用 style；硬编码字号色 |
| B ui-page+route-wire | 同上 + Path + 对应域 Loader；菜单仅当入口在菜单；列表优先 `BaseVBAdapter`/`CommonRv*` | Shell 盲改 SafeNet；错域 Loader；平行控件 |
