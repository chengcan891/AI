# 加功能：讨论方

## 角色边界

- **禁止**改业务源码 / 资源 / 路由。
- 可 Read 约定与仓库范例；定稿后由调度者等用户确认再实现。
- 产出 ≤80 行清单体 `feature-spec.md`；禁止长文散文。

## 阅读切片（省 token）

按顺序打开，**到齐即停**，勿通读约定全文：

1. 约定「按类型速查」→ 选定**主类型**字母 A/B/C/D（复合则另记附属）
2. 约定「域→模块映射」→ 填 UI/Domain 模块
3. 约定对应「五类范例」**仅一条**路径作对照
4. **仅当主类型为 B（或单独 E）** 时再读约定「路由」+ SafeNet 段；**A/C/D 禁止打开路由章**
5. `AGENTS.md`：仅当需要确认编译/加密编辑方式时扫相关段（宿主已加载可跳过全文）

**不要**预读 implement/review 技能；**不要**打开无关范例。

## 决策树

```
有无界面？
├─ 无 → D service（通常无 Route、无 layout）
└─ 有 → 对话框？
         ├─ 是 → C ui-dialog（先问：现有 Dialog 工具能否覆盖？）
         └─ 否 → 需要全局/跨模块入口？
                  ├─ 否 → A ui-nested（同模块容器内打开）
                  └─ 是 → B ui-page + route-wire
```

标签：`ui-nested` | `ui-page` | `ui-dialog` | `service` | `route-wire`（B 常 = page+route-wire；纯 E 少见，优先并入 B）。

### 易混分类（批量真实功能高频）
- 路径含 `/impl/` 或落在 `*Container*` 下 → 默认 **A**，不要挂 Route。
- 已被某 `*PageLoader` 引用或需跨模块打开 → **B**。
- `*Dialog*` / 确认框 → **C**（先 Utils）。
- `core/*/…*Manager*` → **D**（必须写调用方）。
- 文案文件按域：`string-setting.xml` / `string-work.xml` / …，菜单才用 `strings-menu.xml`。

## 类型必问（缺一不可）

| 类型 | 额外必问 |
|---|---|
| A 嵌套页 | 父容器/入口 Fragment？谁 replace/add？**是否 Container 本身**（Container=壳，叶页面另计）？ |
| B 可路由页 | Path 名？哪个 `*PageLoader`？要否 `strings-menu.xml`？SafeNet？**先搜 Loader 是否已引用同名 Fragment** |
| C 对话框 | Utils/Notice 能否覆盖？输入框？调用方？**禁止**为 Dialog 加 PageRoute |
| D 无界面 | 哪个 `core-*`？**调用方类路径**（无调用方则停）？禁 UI/Route |
| E 接线 | 与 B 成对：Path + Loader +（可选）菜单；单独 E 必须写明配对页面已存在或同单交付 |

## 复合功能与分期（省 token / 防跑偏）

1. 识别复合（多宿主、或 UI+协议+算法+地图横切）→ **必须**在 spec 写「本期 / 下期」。
2. **本期默认**：宿主 UI + 参数绑定 + 模拟/桩调用；真协议、真算法库、真地图、**全语言翻译同步**标下期或后续实现轮，除非用户书面要求一次交付。
3. **未写分期的复合功能 = 讨论未完成**，不得标「定稿候选」。
4. **首轮探索**：只定位宿主页/layout + 一条对照范例；协议/算法/地图细节进「待澄清」，本轮不搜。
5. **先交流 / 草稿轮**：宿主定位 Glob/定向 Grep **≤3**；深域不搜。
6. **修订轮**：见专节；探索预算归零为主，勿重复草稿探索。

## 外部设计文档（md / 图片 / pdf）

有设计图 / mockup / 截图时：**禁止**以「样式已复用 / 对照范例页」为由跳过版式还原。
检查表须写清示意图构图要点与单位控件形态；**占位图默认不算**检查表该项通过。
必须在 feature-spec 写出 **UI 还原检查表**（见模板节），并在讨论正文中**逐项显式列出**（不可只写「按设计」）。

设计图路径须写入 feature-spec（相对仓库或用户给出的路径），供实现/验收对照。
具体用哪套控件、单位 helper、样式名：写入检查表时**引用当前项目的 conventions 技能**，不要在本技能里假设某框架类名。

既有约束：
- 外部文档只抽取与本期相关的验收与约束；大文档用摘要，不整篇贴进 Task。
- 有图时路径必填；无图则检查表整节可删。

## 先交流 / 澄清优先

用户说「有问题先交流」「清楚后再做」时：

1. 先列出 ≤8 条澄清问题（分期边界、模拟 vs 真协议、宿主是否已确认等）。
2. 可写 **草稿** `feature-spec.md`（标题注明「草稿·待澄清」），含开放问题清单。
3. **立即结束本轮**，把问题交回编排方/用户；**禁止**在未回复前继续 Grep 协议/算法/地图。

无「先交流」口令、但信息仍不够填类型必问表时：同样落盘草稿 + 澄清问题并停，勿为填表深挖全栈。

## 探索预算（硬限制）

| 轮次 | 工具调用硬上限 | 约定 Read | 设计图 Read | 其它 |
|------|----------------|-----------|-------------|------|
| 先交流 / 草稿 | **≤10** | **≤1**（整轮累计；优先 offset/limit） | **≤2** 整轮合计 | 宿主定位 Glob/Grep≤3 |
| 修订（澄清后） | **≤6** | **0**（禁再读约定） | **0** | Grep/Glob≤2 且仅补路径 |

- 找文件用 **Glob**。**禁止**空 `pattern` 的 Grep（带 glob/path 也不行）。
- 超上限：先落盘 `feature-spec` 草稿或澄清问题再停；禁止「再搜一轮更安心」。
- 同文件不重复 Read；同关键词 Grep 失败一次后改 Glob。
- 禁止批量读 jpg/pdf、禁止整本 pdf。路径写入 spec 即可。

## 执行步骤

1. 按阅读切片取约定 → 定**主类型**；若复合则写附属类型 + 建议分期（见上节）。**A/C/D 勿开路由章。**
2. 外部文档：先 md，设计图路径可多列，整轮 Read≤2；用户要求先交流则先列澄清问题（见上节）。
3. 问清类型必问表 + 一句话目标 + 数据依赖。信息不够先提问并落盘草稿，**不要臆造模块**，**不要**为填表深挖全栈。
4. 写 `feature-spec.md`（模板下）；「影响文件清单」具体到相对路径草案；有 UI 必填 **UI 绑定表**；实现与验收共用此表，定稿后冻结。A/C/D 的「禁止改动」必须写明 `PageRoute/*PageLoader`；**删除 Route/菜单节**（勿留空章）。
5. 回复：路径 + ≤8 条待确认要点 +「请确认后再实现」（有开放问题则明确「请先答复澄清」）。

## UI 还原检查表（有设计图时必填）

设计图存在时本节不可删、不可写「N/A / 样式复用即可」。缺任一项 = 讨论未完成。
**字段保持通用**；项目具体控件 / 单位 API / 样式名填在「规格写入」列，并指向 conventions，勿在本技能正文写死某项目类名。

| 项 | 设计要求（对照图） | 规格写入 |
|----|-------------------|----------|
| 布局分区 | 设计中的主要区域（如顶栏 / 标签栏 / 主内容左右栏 / 底栏等，以图为准） | 有无、相对位置与大致比例 |
| 标签栏文案 | 完整标签列表（逐字） | 列表 |
| 标签栏对齐 | 是否居中 / 均分 / 其它（以图为准） | 是/否 + 实现时查 conventions 的对应组件 |
| 示意图 / 插图区 | 设计若有独立图示区：写清构图要点（铺满？线组？标注序号在图内？定位点？） | 独立视图；**默认占位不可单独过 UI 还原轮**；规格写「占位则视觉未验收」 |
| 表单 / 数据区布局 | 行式、列表、网格等（以图为准）；禁止「按常用表单」含糊带过 | 逐行/逐块字段；设计垂直标签行则写明禁 2x2 |
| 序号 / 徽章 vs 文案 | 设计中的序号、徽章是否与标签文字分离 | 独立控件；**不得**把序号写进 label 字符串 |
| 计量单位 | 存储单位、显示换算、单位控件形态（独立 TextView / 内嵌单位输入） | 引用 conventions；禁止业务硬编码单位字面量；形态写死一种，勿留「均可」 |

## 修订轮（澄清答复后）

当 `loop-state.md` 已含「澄清答复」且任务是修订定稿候选时：

1. **只读**：本技能（若未读）+ `loop-state.md` + 现有 `feature-spec.md`。**约定 Read=0**；**设计图 Read=0**。
2. **主工作**：合并答复 → 定稿候选；更新绑定表/验收/分期/检查表/禁止项。复合则核对本期是否仍过宽。
3. **探索**：Grep/Glob **≤2**，仅补清单缺的相对路径。**禁止**再搜协议真实现、地图/生命周期全链路。
4. **顺序**：先改 `feature-spec.md`，再可选极短核对。
5. 写完停：请用户确认定稿；**禁止**进入实现。
6. 工具调用整轮 **≤6**。

## 禁止
- 复合功能未写本期/下期就标定稿候选；或草稿/修订轮超过探索硬上限仍继续搜
- 有设计图时跳过 UI 还原检查表，或用「样式已复用」代替分区/对齐/徽章/单位/按钮等显式项

- 禁止 Grep 空 pattern（**即使带 glob/path 也不行**；找文件用 Glob）。
- 禁止为填协议/算法细节而超过探索预算。
- 禁止批量 Read 设计 jpg/pdf；禁止整本 pdf。
- 禁止 A/C/D 打开或填写 Route/菜单章。
- 不改业务文件；不把项目模块名写进本 SKILL（只写进本次 spec，且来自约定）。

> ag6.0：`PageRoute` 与全部 `*PageLoader` 均为 SafeNet 锁定。B/E 讨论只写 Path **名草案**，勿要求贴明文；实现方 IDE 追加。

## 参数页 / 多 Tab 必冻项
参数编辑 / 多 Tab / 单位 / 示意图类需求，在 feature-spec **冻结**前追问并写入（缺则澄清轮，勿丢给实现猜）：

- 宿主是「单页」还是「Tab + 子页」？不支持的类型是否隐藏 Tab？
- 确定/取消是共享页脚还是每 Tab 自有？确定后是否留在当前 Tab？
- 物理量：存库基准单位 vs 展示单位；单位标签独立还是塞进文案？
- 应用开关关闭时：仍校验并保存全字段，还是灰显/跳过校验？
- 依赖字段越界：静默 coerce 还是报错阻挡？
- 示意图与参数徽章字母/色对照表（写入 UI 还原检查表）。
- 主对象下发到设备后，哪些路径必须联动二次下发（列清单，避免只接一条路径）。
- 算法/设备若仍为 stub，验收标准写「接口已接但行为待算法」还是「本轮必须真生效」。

- 范围交互：控件硬限制 + 置灰确定，还是允许输入后 Toast？
- 主对象下发后，设备是否自动清除未启用的从属参数？（决定 skip-disabled）
- 从属下发失败时，是否阻止进入会话/驾驶？
- 参数序号徽章用数字还是字母？当前位置徽章是否必须与地图定位图标一致？
