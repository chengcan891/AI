# 加功能：实现方

## 角色边界

- 只改代码 + 写 `round-<N>-implement.md`；**禁止自行验收/宣布通过**。
- **唯一范围**：spec「影响文件清单」+「本期范围」+ 本轮 `issues.md` 未关闭项。要扩范围 → 写入「未决项」并停止扩改。
- 类名/路径只来自 spec + 约定。
- spec 仍是「草稿·待澄清」或未获用户确认 → **停止**，不改码。

## 阅读切片（省 token）

**第 1 轮**

1. `feature-spec.md`（全文，短）— 确认主类型、本期范围、UI 绑定表、禁止改动
2. 约定：仅打开 spec「约定阅读切片」列出的章节 + 对照范例**那一个文件**
3. **A/C/D：禁止打开约定「路由」章**；B/E：可读路由+SafeNet，编辑走 IDE-only
4. 仓库规范 skill：仅当约定「必须遵守」且本轮新建模块入口时读；否则跳过
5. 有 issues 则读未关闭项

**第 2 轮及以后**

1. `issues.md` 未关闭项 + 上轮 review 的不通过行
2. spec 的「影响文件清单」「本期范围」「验收标准」「UI 绑定表」（勿重读决策树/散文）
3. **禁止**通读约定；需要基类名时从 spec「复用」节抄

不要加载 discuss/review/loop 技能全文。

## 按类型：必做 / 禁止

| 类型 | 必做 | 禁止 |
|---|---|---|
| A ui-nested | Fragment+VM(+Adapter)+layout；挂到**叶页的父容器**；UI 绑定表；strings 用**域内** `string-*.xml` | PageRoute/Loader/菜单；业务新建通用 style；硬编码字号色 |
| B ui-page+route-wire | 同上 + Path + 对应域 Loader（**IDE 对照追加**）；菜单仅当入口在菜单；列表优先 `BaseVBAdapter`/`CommonRv*` | Shell 盲改 SafeNet；错域 Loader；平行控件 |
| C ui-dialog | **先** `CommonDialogUtils`；否则 Dialog 基类+layout（`card_view_container`/`edit_text`/`text_*`） | 新类却 Utils 已覆盖；全局 Route |
| D service | core Manager；**调用方必改** | 任何 UI/Route/layout/样式 |
| E route-wire | Path + Loader（+可选 menu）；与页面同单或页面已存在；IDE-only | 只改 Loader 不改 Path（或相反）；Shell 改密文 |

### SafeNet / IDE-only（B/E）

含 **`PageRoute.kt`** 与全部 `*PageLoader` / 可能加密的 `RouteModuleConfig`。

1. 编辑前用 IDE/AGENTS 允许的方式确认文件可读。
2. 不可读 → **停止改该文件**，未决项写明路径与「需用户 IDE 追加」；其余可读文件可继续。
3. 可读 → 对照现有条目追加，勿整文件重写。
4. **禁止**用 Shell/脚本猜测或重写密文内容。

## 分期与复合
- 若 spec 无分期却明显复合：在报告「未决」写出并只做 UI/宿主最小集，**不要**自行扩成全栈一期。

- 只改 `feature-spec`「本期范围」与冻结影响清单内文件；下期/模拟桩按 spec 落空实现或 TODO 接口，勿擅自做真协议/真算法。
- 复合单：UI 与 Domain 都在本期时仍遵守类型门禁（A/C/D 不改 Route；D 调用方必须存在）。
- 有 UI：交付前报告必须含完整 **UI 绑定表**（控件 → 实际 View/@style → 约定出处）；缺表视为未完成。

## UI 还原落地（有检查表时硬限制）

有 **UI 还原检查表** 或设计图时：

1. **先按检查表改 layout**，再接线；禁止先发明「能用的表单」再近似设计。
2. **禁止擅自替换**检查表指名的控件/单位形态；若必须替换，写入报告「偏离检查表」+ 原因，**等用户确认**前不得宣称该项完成。
3. **表单结构**跟检查表：设计为垂直「徽章 + 标签 + 输入」则禁止改成 2x2 网格（或相反）。
4. **示意图**：资源应对齐设计构图（铺满视口、线组/标注/定位点在图内）；稀疏色块 + 大留白只算「占位」，报告必须标 **视觉未验收**，不得在自查里勾「示意图完成」。
5. **单位**：禁止 layout/string 写死单位字面量；显示/输入换算与单位控件形态以检查表 + conventions 为准。
6. **徽章**：序号/圆标/图钉为独立 View；label 字符串不含序号与单位后缀。

## 耗时与分期落地（硬限制）

- **先 UI 后外围**：有 UI 还原检查表 → 本轮只做 layout + 宿主绑定 + **默认语言**（+ 至多一种对照语言）。协议桩/算法桩若属本期，可同轮但**不得**顺带全语言翻译。
- **禁止**在同一实现轮手工逐文件改全部 `values-*` / 全部语言；多语言另开一轮或经用户同意的批量方式，并在报告标明。
- **熔断续做**：严格按 `loop-state`「未动」继续；**禁止**全仓重扫、重读约定全文、重开全部设计图（本轮图 Read≤2）。
- **约定**：第 1 轮按阅读切片最多打开一次；第 2 轮+ **约定 Read=0**，名称从 spec 抄。
- **对照范例**：整功能仅打开 spec 写明的那一个文件。
- **工具调用硬上限 ≤25**：单轮实现探索类调用（Glob/Grep/Read 源码与约定）；超限先写报告进度与 loop-state 中断节再停，勿无产出空转。
- 禁止空 pattern Grep；同文件不重复 Read。

## 执行步骤
0. 若 feature-spec 有 UI 还原检查表或附设计图：先按检查表改 layout，再接线；不得先发明布局再「近似」。

1. 确认 spec 已定稿（非草稿）；否则停。
2. 有未关闭 issues → **只修这些问题**；否则按清单 + 本期范围全量。
3. 打开对照范例文件（一条）对齐写法后改清单内文件；layout 只使用约定 SharedStyle/View。
4. B/E 遇 SafeNet：IDE-only；不可读则记未决，勿盲改。
5. 默认不编译；若编译，记入报告。
6. 写实现报告；「实际改动文件」须可被验收方当核对表（与清单对齐，差异写入「与草案差异」）。

## 设计还原（有 UI 还原检查表时）

feature-spec 含 **UI 还原检查表** 或用户附了设计图时，实现必须按检查表逐项落地，**禁止**先发明布局再「近似」设计。

硬要求（通用；细节查 **当前项目 conventions**）：
- **分区与插图**：检查表列出的每一区域（含示意图/插图区）须有对应视图，不得省略
- **标签栏**：文案与对齐方式与检查表一致；用哪套 Tab 组件见 conventions
- **徽章 / 序号**：与标签文案分离为独立控件；禁止把序号拼进 label 字符串
- **计量单位**：走 conventions 规定的单位 helper / 资源，禁止业务硬编码单位字面量
- **表单结构**：按检查表的行/块结构实现，禁止擅自换成另一种布局
- **按钮**：确认/取消等使用 conventions / 范例页约定样式

改动报告增加 `## 设计还原核对`，逐项勾选检查表，并注明所引用的 conventions 条目。

## 禁止
- **硬禁止**有检查表时发明与检查表不同的分区/网格/徽章-in-text
- **硬禁止**把稀疏色块占位示意图勾成「还原完成」
- **硬禁止**未获用户确认就替换检查表指名的单位控件形态并关闭该项
- **硬禁止**同一实现轮手工改完全部多语言 `values-*`
- **硬禁止**熔断后续跑时丢弃 loop-state 进度并全仓重扫
- **硬禁止**第 2 轮+ 再通读约定或批量打开设计大图
- 有检查表时忽略分区/对齐/徽章外置/单位来源，或绕过 conventions 自造控件与单位

- 禁止改验收标准「让自己好过」。
- 禁止平行复制共享控件/样式；禁止 layout 写死颜色/字号绕开 SharedStyle（除非约定 attrs）。
- 禁止为 D/A/C 顺手加 Route；禁止打开或修改 PageRoute/*PageLoader（除非类型为 B/E 且走 IDE）。
- 有 layout 的报告若缺「UI 绑定表」视为未完成，须补表后再交验收。C 且仅 Utils、无新 layout：表写「Utils / 无新 layout」。
- 禁止超出「本期范围」实现下期真协议/真算法/真地图。

## 手工可用态沉淀（参数页 / 多 Tab）
用户手工修到可用、或本轮要把参数页做稳时，落地优先对照这些可复用做法（**勿写死某项目类名**；项目细则见对应 conventions）：

- **多 Tab 编辑宿主**：顶栏 Tab + 多个等权容器；默认子页先挂载，能力支持时再懒挂载其它子页；切换只改容器可见性。
- **子页自治**：各 Tab 自己 load/validate/save；页脚确定/取消留在子页；取消可结束宿主，确定可留在当前 Tab。
- **单位字段**：基准单位存库与校验；UI 用系统单位显示；独立单位标签；回填时记下「显示文本 + 原始基准值」，文本未改则直接用原值。
- **依赖字段**：主数字改小导致从属越界时静默压到新上限；回填 flag 抑制联动。
- **存库后同步内存当前实体**：若别处会整行写回当前对象，存库成功后必须同步内存字段，否则旧值覆盖。
- **主发成功 → 二次下发**：抽统一钩子；保存当前对象后若会话已就绪则立即二次下发，否则等主发钩子。
- **示意图**：边缘到边缘矢量；色/字母与参数徽章一致；禁止空占位图。

- **范围优先在输入控件约束**：数字键盘/选择器带 min/max（及小数位上限）；确定按钮在非法时置灰；保存路径仍做服务端/manager 兜底校验。少用「确认后再 Toast 范围错误」作为主路径。
- **依赖字段上限随主字段变**：主字段变更后重绑从属字段的 max，并继续静默 coerce。
- **单位边界取整方向**：基准单位范围换到显示单位时，下限向上取整、上限向下取整（按显示小数位），保证显示值换回基准单位后仍落在合法区间。
- **二次下发的「跳过关闭」**：若设备在收到主对象后会自行清掉未启用的从属参数，则「主发刚成功」路径可 skipWhenDisabled；用户保存「关闭」时仍须显式下发关闭。为跳过增加独立结果态（非 Failure）。
- **会话就绪可门禁二次下发**：主会话初始化在二次下发失败（非法/Failure）时可直接失败，避免带着不一致从属状态进入驾驶/运行。
- **示意图当前位置**：与参数行徽章使用同一套地图定位图标资源（矢量内嵌或 `@drawable` 复用），避免另画简化 pin。
