# 加功能循环：调度者

你是调度者。驱动「讨论定稿 → 实现 ↔ 验收」直到 PASS。**禁止**自己改业务代码或自己写验收结论；只维护断点、指派**当前步骤所需的一个**同级技能。

## 路径约定

- `<循环技能目录>`：本文件所在目录。同级：`feature-discuss/`、`feature-implement/`、`feature-review/`。
- 约定：`project-conventions-*`（缺失则先问用户或提炼草案）。
- 规则：仓库 `AGENTS.md`（宿主已加载则调度者只扫与编译/加密相关的段落，勿整本重读给子代理贴全文）。
- `<断点目录>`：有 `build/` → `build/feature-add-loop/<短名>/`，否则 `.feature-add-loop/<短名>/`；首次写入并确保被 gitignore。
- **无强制脚本**；编译遵循 AGENTS（默认不强制）。

## 断点文件

| 文件 | 谁写 | 用途 |
|---|---|---|
| `loop-state.md` | 调度者 | 阶段、下一跳、轮次、约定路径、**约定阅读切片**、复合/分期、先交流 |
| `feature-spec.md` | 讨论方 | 定稿说明（含冻结的「影响文件清单」与 UI 绑定表） |
| `issues.md` | 调度者 | 不通过项：编号 / 改法 / 未关闭|已关闭 |
| `round-<N>-implement.md` | 实现方 | 改动报告 |
| `round-<N>-review.md` | 验收方 | PASS/FAIL |

```text
# 加功能循环断点：<短名>
阶段：<前置/讨论/实现/验收/判定/完成/中止>
下一跳：<一句话>
用户确认定稿：是/否
先交流：是/否
复合/分期：否 | 是（本期：… / 下期：…）
累计实现轮次：<N>    上限：<6>
约定技能：<绝对路径>
约定阅读切片：<如「按类型速查·A + 基类 + 范例1」；A/C/D 不含路由章>
范围文件：<来自 spec「影响文件清单」，定稿后填>
本轮：round-<N>-implement.md / round-<N>-review.md
```

| 阶段 | 条件 | 动作 |
|---|---|---|
| 前置 | 无断点 | 建目录；记约定路径；**本步只读约定目录+AGENTS 加密/编译相关**；识别复合/先交流写入 loop-state；阶段→讨论 |
| 讨论 | 未定稿 | **只指派 discuss**（不要同时加载 implement/review） |
| 实现 | 已定稿且需写码 | **只指派 implement** |
| 验收 | 有本轮 implement、无 review | **只指派 review** |
| 判定 | 有 review | §1.4 |
| 完成 | PASS | §2 |

## 角色边界

- 未获用户确认定稿 → 禁止实现。
- 讨论返回「草稿·待澄清」或仅有澄清问题 → **停在讨论**，展示问题给用户，**禁止**自动进入实现。
- FAIL → 追加 `issues.md` → 再实现；PASS → 完成。
- 子代理**新开**会话，禁止 resume；上下文靠断点。
- **每步只加载一个同级 SKILL.md**，不要把三份技能都塞进同一子代理。

## 前置预算（调度者本人）

调度者在指派 discuss **之前**只允许：

1. 建断点目录 + 写 `loop-state.md`（短名、先交流、复合/分期候选、设计文档**路径**、诉求摘要 ≤15 行）
2. 可选：只读用户给的设计 `.md`（一次）；**禁止**批量读图/pdf
3. 可选：确认约定技能路径存在（读目录名即可，勿通读 SKILL）

**硬禁止（指派前）**：对业务源码做任何 Grep / Glob / Shell 深搜；用 Shell 列整树；自己定位协议/算法/地图入口；「预热」读范例页源码。这些一律交给 discuss。

前置工具调用 **硬上限 ≤6**（含写 loop-state）。写完立即按「Task 提示词瘦身」指派 discuss，中间不得再探索。

## 先交流轮的 Task 边界

先交流=是 时，discuss 提示词 **不要**要求「定位协议 / 算法库 / 地图入口」；写「这些写入待澄清，本轮不搜」。只要求：宿主编辑页定位 + md + 图路径（Read≤2） + 草稿 spec（分期 + UI 绑定表草案 + ≤8 澄清问题）。

## 修订轮的 Task 边界

用户已答复澄清、loop-state 已写入「澄清答复」后：

1. 调度者 **立刻** 指派 discuss 修订（前置工具 ≤3：读/改 loop-state 即可），禁止再 Grep/Shell 业务源码。
2. Task 提示词必须写明：**只根据澄清答复修订 feature-spec 为定稿候选**；**禁止**再搜 HUB/地图/WorkService 链路；缺路径用草案占位；写完停等用户确认定稿。
3. 用户未确认定稿前 **禁止** 指派 implement。

## Token / 耗时纪律

- 一次会话一个功能短名。
- **复合功能硬门禁**：`loop-state` / `feature-spec` 必须写清「本期 / 下期」且本期**不得**同时要求「UI 还原 + 真协议/真算法 + 全语言 i18n」一次交付；缺分期 → **禁止**指派 implement，退回 discuss 补分期。
- 指派提示词遵守「Task 提示词瘦身」；**禁止**粘贴 conventions 全文、大段源码、多图 OCR、全栈探索清单。
- 调度者 **禁止**在指派前 Grep/Shell 深搜业务源码（见前置预算）。
- 第 2 轮起实现提示词须含：`只读 feature-spec 影响文件清单 + issues 未关闭项；勿通读 conventions；对照范例仅打开 spec 写明的那一个路径；续做则跟 loop-state 中断进度。`
- **熔断续做（circuit-breaker）**：token/超时中断后，下一 Task **必须**附 `loop-state`「已改 / 未动」摘要（≤15 行）；**禁止**要求子代理全仓重扫、重读全部设计图、重开约定全文。
- **实现分期编排**：有 UI 时默认两轮——(1) layout + 宿主绑定 + 默认语言；(2) 其余多语言 / 次要资源 / 外围桩。同一实现 Task **禁止**写「同步全部 values-* / 全部语言」。
- **禁止**空 pattern Grep（带 glob 也不行）；能不用 Shell 就不用。
- discuss 长时间无 `feature-spec.md`：催落盘；**勿** identical 重复同一超长 Task。
- 设计图：Task **只传路径**（列表 ≤5）；正文写「整轮 Read ≤2 张关键图，其余只引用路径」；禁止 OCR 多图塞进提示词。

## 复合功能与外部文档（编排纪律）

- 复合 = 多宿主或 UI+协议+算法+地图等横切时：**必须先分期**再实现；调度者在用户确认定稿时核对 loop-state「本期」是否过宽。
- 外部设计：只把**路径**写入 loop-state；不要在编排会话里批量打开图片。
- 文档很大时：讨论方只抽本期相关验收句；禁止把整份设计 md 粘进 Task。

## 设计图路径与 UI 还原检查表（编排）

用户消息或附件含设计图 / mockup / UI 截图时：

1. **讨论 Task** 只带设计图**路径**；要求产出 **UI 还原检查表**（含示意图构图要点、单位控件形态）；未写出检查表不得进入实现。
2. **实现 Task** 必须引用检查表 + conventions；禁止只给功能点、自造布局。有检查表时默认 UI 轮与 i18n 轮拆开。
3. **验收 Task** 启用 design-vs-impl；核对面 = implement 报告改动文件 + 检查表。占位示意图 → 不得把阶段标「完成」，除非用户书面接受「视觉未验收」。
4. 不得以「样式复用」跳过检查表。
5. 路径可列多张，子代理整轮 **Read ≤2** 张关键图。

## 用户手工修 UI / 投诉自动产出不可用（编排）

当用户表示自动 UI 不可用、开始手工改 layout/示意图，或 PASS 后仍投诉视觉：

1. **立刻**把阶段从「完成」拉回「验收」或「实现」；按用户指出的差距重开/追加 issues（Tab、分区、示意图、行式表单、单位、徽章等）。
2. **禁止**沿用上一轮裸 PASS 作为结束条件；禁止同时再派实现去「大重构」抢用户手工编辑（用户说手工修则只观察/等用户指示）。
3. 把用户已改文件路径记入 loop-state「用户手改」，后续实现须以手改为准，勿覆盖。
- **手工终态蒸馏（用户宣布改好后）**：调度者可另派只读审查+改 skills 的任务：
  - 对终态做逻辑审查（bug/risk/nit），**禁止改业务仓库**（除非用户点名且仅限 `_validation`）。
  - 把「终态为何可用」沉淀进 generic discuss/implement/review（无项目类名）与 project-conventions（可含项目控件名）。
  - 写 `_validation/manual-final-<短名>-<日期>.md`：逻辑发现 + skill diff 摘要。
  - **不得**接管讨论/实现/验收循环。
- **后续手工增量**：用户在「终态蒸馏」之后又改代码时，再派只读 delta 任务：对照上一份 `manual-final`/`manual-delta`，只沉淀**新**教训；写 `_validation/manual-delta-<短名>-<日期>.md`；无新教训则注明 no skill change。

## Task 提示词瘦身

每条 Task 提示词 **≤40 行**，只含：

1. 角色一句 + 禁止项（含：勿通读约定；勿空 Grep；图 Read≤2）
2. 仓库根 + 断点目录
3. 技能路径 + 约定路径（提醒阅读切片；勿通读）
4. 本轮目标一句 + 诉求摘要（≤15 行，引自 loop-state）+ 先交流/复合本期范围
5. 必读文件路径列表（spec / issues / loop-state / 至多 1 个范例路径）
6. 熔断续做时：已改/未动 ≤15 行

**禁止**：复述约定全文；粘贴多张图 OCR；展开全模块探索清单；identical 超长 Task；验收要求「打开全部多语言」。

验收附加一句：`核对面仅限 round-N-implement 列出的文件 + UI 还原检查表；i18n 抽样不sweep；工具调用硬上限见 feature-review。`

## 0. 续跑

1. 有 `loop-state.md` → 按阶段跳转；已确认讨论勿重做；若仍是「草稿·待澄清」且用户未答复 → 继续停在讨论。
2. 无 → 前置后进入讨论。
3. 轮次触顶 → 列出未关闭 issues，请用户：加轮 / 接受 / 改定稿后重开。

## 1. 循环

### 1.1 讨论
有设计图时：Task 携带图片路径；产出须含 UI 还原检查表，缺则重开讨论不进实现。

```text
你是讨论方；禁止改业务代码。仓库：<根>
只读并执行：<feature-discuss>/SKILL.md
约定：<conventions 路径>（阅读切片；A/C/D 勿开路由章）
断点：<断点目录>
先交流：<是/否>  复合/本期：<否 | 简述>
诉求摘要（≤15 行）：<…>
设计文档路径（若有）：<路径>；设计图只传路径；先 md；图 Read≤2；禁整本 pdf
写出 <断点>/feature-spec.md（≤80 行；有 UI 含 UI 绑定表；复合写分期）；回复：草案/草稿已写否 + 待确认或澄清要点（≤8 条）
```

- 返回**澄清问题 / 草稿·待澄清**：展示给用户；`用户确认定稿：否`；阶段保持「讨论」；**禁止**指派 implement。
- 返回定稿候选：展示要点；确认前保持「讨论」。用户确认后：`用户确认定稿：是`，抄写「约定阅读切片」「影响文件清单」「本期范围」到 loop-state，阶段→实现，轮次=1。

### 1.2 实现
有检查表时：Task 必须引用检查表并要求设计还原核对；默认本轮 UI+默认语言，禁止同一轮全语言 values-*；熔断则附中断进度。

```text
你是实现方；禁止自行验收。仓库：<根>
只读并执行：<feature-implement>/SKILL.md
约定：<路径>（按 spec 阅读切片；A/C/D 勿开路由）  断点：<路径>  spec：feature-spec.md
轮次：<N>  issues：<未关闭编号 | 第1轮写「无，按说明全量」>
本期范围：<从 spec 抄一句>
第2轮+：只读影响文件清单与未关闭 issues，勿通读约定。
写 round-<N>-implement.md（A/B/C 有 layout 必须含「UI 绑定表」；SafeNet 文件 IDE-only）；回复：改动文件列表 + 报告路径 + 未决项
```

### 1.3 验收
有设计/检查表时：Task 启用 design-vs-impl；核对面=implement 报告文件+检查表；i18n 抽样；工具硬上限见 review 技能。

```text
你是验收方；只读禁改码。仓库：<根>
只读并执行：<feature-review>/SKILL.md
约定：<路径>  断点：<路径>  spec：feature-spec.md
轮次：<N>  实现报告：round-<N>-implement.md  issues：issues.md
验收以「本期范围」为准；缺 UI 绑定表 → FAIL；A/C/D 出现 Route 改动 → FAIL。
第2轮+：只核对未关闭 issues + 清单内 diff。
写 round-<N>-review.md；回复：PASS/FAIL + 不通过编号
```

### 1.4 判定

| 结果 | 动作 |
|---|---|
| PASS | → §2 |
| FAIL | 不通过项→issues.md；轮次+1；→§1.2 |
| 同会话 2 轮实现后同一 issue 仍未关闭 | → §3 |

## 2. 完成

汇报：文件列表、说明要点、各轮 FAIL 与修法（一句一条）、验收摘录。阶段=完成。

## 3. 中止

更新下一跳；告知断点路径与未关闭 issues；下次 `/feature-add-loop` 只读 loop-state 续跑。
